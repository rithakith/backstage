# Plugin Suite Architecture

The WSO2 plugin suite is split into frontend display, backend runtime operations, catalog ingestion, and optional Asgardeo identity integration.

## High-Level Flow

```text
WSO2 API Manager / gateways
  -> catalog-backend-module-wso2-apim
  -> Backstage catalog API entities
  -> wso2-api-manager frontend entity cards

wso2-api-manager frontend
  -> discoveryApi.getBaseUrl('wso2-api-manager')
  -> wso2-api-manager-backend routes
  -> WSO2 Publisher, DevPortal, Service Catalog, and gateway discovery endpoints

Asgardeo
  -> catalog-backend-module-asgardeo
  -> Backstage User and Group entities

Asgardeo OIDC
  -> auth-backend-module-asgardeo-provider
  -> Backstage auth provider id 'asgardeo'
```

## Frontend Plugin

The frontend plugin is registered with plugin id `wso2-api-manager` in `plugins/wso2-api-manager/src/plugin.ts`.

It provides:

- A routable `Wso2ApiManagerPage`.
- Entity cards for WSO2 API overview, API definition, documents, about information, MCP tools, and API product resources.
- API refs for the WSO2 backend client and WSO2 auth integration.
- An alpha frontend-system plugin in `plugins/wso2-api-manager/src/alpha/plugin.tsx`.

The frontend reads WSO2 metadata primarily from Backstage catalog entity annotations generated by the catalog backend module.

## Backend Plugin

The backend plugin is registered with plugin id `wso2-api-manager` in `plugins/wso2-api-manager-backend/src/plugin.ts`.

It mounts routes from `createRouter` and depends on:

- `coreServices.httpAuth`
- `coreServices.httpRouter`
- `coreServices.logger`
- `coreServices.rootConfig`
- `coreServices.userInfo`

The backend plugin performs runtime operations that should not be executed directly from the browser against WSO2, such as service-account token use, WSO2 API proxy calls, gateway discovery, document streaming, and WSDL streaming.

## Catalog Backend Module

The WSO2 APIM catalog module is registered as a backend module for the Backstage `catalog` plugin:

- `pluginId`: `catalog`
- `moduleId`: `wso2-apim`
- Provider id used by the module: `wso2-publisher-apis`

It creates `Wso2ApiEntityProvider`, adds it through `catalogProcessingExtensionPoint`, and schedules it using `catalog.providers.wso2Apim.schedule`.

The provider performs full catalog mutations. Each run replaces the provider-owned set of entities using the provider location key.

## Asgardeo Integration

The Asgardeo catalog module registers a catalog provider with id `asgardeo`. It fetches SCIM groups first, then users, and applies a full mutation containing both entity types.

The Asgardeo auth module registers an auth provider:

- `providerId`: `asgardeo`
- Authenticator: Backstage OIDC authenticator
- Sign-in resolvers:
  - `emailLocalPartMatchingUserEntityName`
  - `emailMatchingUserEntityProfileEmail`

Asgardeo is optional for the WSO2 API Manager plugin UI, but useful when Backstage sign-in and catalog users/groups should come from Asgardeo.

## External Systems

The implementation uses these WSO2-facing API families:

| External API family | Used by | Purpose |
| --- | --- | --- |
| WSO2 Publisher API | Catalog module and backend plugin | API list, API details, revisions, documents, WSDL, settings, API products, MCP servers. |
| WSO2 DevPortal API | Backend plugin | API key generation. |
| WSO2 Service Catalog API | Catalog module and backend plugin | Service listing, usage, and definitions. |
| Self-hosted gateway discovery URLs | Catalog module and backend plugin | Gateway-discovered APIs and gateway status data. |
| Asgardeo SCIM 2.0 API | Asgardeo catalog module | User and group ingestion. |
| Asgardeo OIDC | Auth backend module | Backstage sign-in. |
